# Commerce API 작업 지침

- 합의된 계약, 기대값, 패키지 의존성을 따른다.
- 정책이 정해지지 않았거나 요구사항을 여러 방식으로 해석할 수 있으면 구현 전에 먼저 질문한다.
- 기능을 변경하기 전에 이번 작업에서 바뀔 책임, 대상 파일, 관련 테스트를 먼저 제안한다.
- 한 번에 작은 기능 단위로 구현한다.
- 구현 후 diff를 검토하고 관련 테스트, lint(Checkstyle), ArchUnit 검사를 실행해 결과를 확인한다.
- 검사를 통과시키기 위해 테스트나 기대값을 삭제하거나 완화하지 않는다.
- 검사를 통과시키기 위해 Checkstyle 또는 ArchUnit 규칙을 삭제하거나 완화하지 않는다.
- 정책, 검사 기준 변경 또는 `apps/commerce-api` 밖의 개편이 필요하면 먼저 이유와 영향을 설명하고 사용자 확인을 받는다.
